# 1분 양궁 게임 프로토타입 명세

## 목적

공개 난수 비컨의 펄스를 재현 가능한 규칙으로 0~9 숫자 세 개로 변환하고, 이를 세 발의 양궁 점수로 보여주는 브라우저 프로토타입을 만든다. 이번 버전은 시각적·기능 검토용이며 베팅이나 금전 보상은 다루지 않는다.

## 범위

- 데스크톱·모바일에서 한 페이지로 실행되는 정적 웹 앱
- NIST Beacon 2.0 chain 2의 1분 주기 펄스 사용
- 매 분 :00에 라운드가 시작되고 :50에 선택 접수 마감
- 해당 마감 시각보다 뒤에 생성된 첫 분 정각 펄스를 라운드 결과 입력으로 지정
- 세 발 숫자를 난수 원문에서 순서대로 생성하고 각 발을 애니메이션으로 공개
- 홀짝, 언더/17/오버, 페어, 트리플, 펄스·계산 근거 표시
- 베팅, 계정, 서버 기록·정산, 실제 보상은 제외

## 결과 생성 규칙

1. 대상 펄스는 `timeStamp`가 라운드 접수 마감 시각보다 큰 최초의 정각 펄스다. 펄스 시각은 UTC 기준으로 비교한다.
2. 대상 펄스의 `localRandomValue`를 왼쪽부터 두 16진수 글자씩 읽어 1바이트로 해석한다.
3. 0~249인 바이트는 10으로 나눈 나머지를 화살 숫자(0~9)로 쓴다. 250~255인 바이트는 버리고 바로 다음 바이트를 읽는다.
4. 바이트를 순서대로 소비해 숫자 세 개를 얻는다. 소비 위치와 건너뛴 바이트를 결과 증명에 기록한다.
5. 가용 바이트를 모두 소진하면 대체 난수를 만들지 않고 해당 라운드를 오류/무효로 표시한다.
6. 세 숫자와 원본 펄스 JSON을 공개 링크에서 재조회할 수 있도록 펄스 식별자와 시각을 표시한다.

## 게임 판정

- 숫자 0은 10점, 1~9는 숫자 그대로 점수로 계산한다. 총점 범위는 3~30점이다.
- 홀/짝은 총점을 기준으로 한다.
- 언더: 총점 3~16, 17점: 별도, 오버: 18~30.
- 페어: 세 화살 숫자 중 정확히 두 숫자만 같다. 세 숫자가 모두 같은 경우는 페어가 아니라 트리플이다.
- 트리플: 세 숫자가 모두 같다.

## 사용자 흐름

1. 화면에 현재 라운드의 마감 시각과 대상 펄스 시각을 표시한다.
2. 사용자가 홀/짝, 언더/17/오버, 페어/트리플 예측을 고른다. 예측은 로컬 화면에서만 저장되고 마감 후 잠긴다.
3. 마감 시각 이후 대상 펄스가 제공되면 바이트를 변환한다.
4. 세 화살을 차례로 쏘는 애니메이션으로 숫자와 점수를 공개한다.
5. 총점·분류·사용 바이트·펄스 번호/시각/원문 링크와 사용자 예측 결과를 보여준다.

## 안전·운영 한계

- 브라우저 시계만 사용하는 프로토타입이므로 사용자가 기기 시각이나 페이지 코드를 바꿀 수 있다. 실제 경쟁/보상용 공정성 시스템으로 간주하지 않는다.
- 공개 펄스는 결과 생성 뒤 즉시 재계산 가능하다. 예측 접수·마감 증명과 이력의 운영자 조작 방지를 위한 서버 측 감사·서명 체계는 후속 범위다.
- NIST 응답이 지연되거나 대상 펄스를 조회할 수 없으면 임의의 다음 펄스로 대체하지 않는다. 동일 대상 펄스를 재조회하고 계속 실패하면 무효/오류로 표시한다.
- 펄스 조회 실패와 CORS 한계를 화면에 숨기지 않는다. 이 프로토타입은 HTTPS로 받은 펄스를 원문 링크와 함께 보여주고 계산을 재현하지만, NIST 인증서 체인/전자서명을 자체 검증하지 않는다는 점을 화면에 밝힌다.

## 완료 조건

- [ ] 반응형 화면에서 1분 타이머와 마감 시각이 보인다.
- [ ] 0~249 및 250~255 변환 경계, 순차 소비, 3개 결과 생성이 테스트된다.
- [ ] 0점수=10점, 총점 홀짝/언더·17·오버, 페어·트리플 판정이 테스트된다.
- [ ] 선택은 마감 후 잠기고, 결과 공개 순서가 세 발 애니메이션과 일치한다.
- [ ] 펄스 조회 실패를 오류로 알리고 다른 펄스로 조용히 대체하지 않는다.
- [ ] 결과에서 원본 펄스와 계산 과정을 사람이 확인할 수 있다.
